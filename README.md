# HardAdmin

Внутренний сервис для IT-отдела. Ведёт учёт оборудования
компании и помощь в обработке заявки сотрудников.

Проблема, которую решает: обычно различное оборудование учтено Exel файлах, 
а заявки могут теряться на электройной почте. Здесь всё в одном месте.

## Что умеет

- Сотрудник создаёт заявки: выдача оборудование, ремонт, списание.
- отдел HelpDesk видит очередь новых заявок, берёт в работу, закрывает с результатом.
  При закрытии заявки на ремонт отмечается, починено оборудование или нет:
  починено — возвращается в работу, нет — уходит на склад как неисправное.
- Выдача и возврат оборудования работают только через заявку:
  выдать или списать без заявки нельзя, заявка закрывается автоматически.
- Реестр оборудования с поиском и фильтрами, реестр сотрудников,
  карточка единицы оборудования с историей заявок.
- Роли: сотрудник видит только свои заявки, Сотрудник отдела HelpDesk — всё и операции
  с оборудованием, суперпользователь — окночательное списание (строка об оборудовании не удаляется) в админке.
- Почтовые уведомления через Celery на заявки и письма, если
  новую заявку никто не взял за 2 часа или статус в работе более двух недель.
- Реализованы тесты на pytest.

## Стек

Django, PostgreSQL, Celery + Redis, MailHog для писем (тест), pytest, Adminer(работа с таблицами).
Всё работает через Docker.

## Как запустить

Для запуска необходим Docker и docker-compose.

```bash
docker compose up --build
```

## После старта:

#сайт — http://localhost:8000

админка — http://localhost:8000/admin

письма — http://localhost:8025 (MailHog)

таблицы БД — http://localhost:8080 (Adminer: PostgreSQL,  сервер db,
пользователь hardadmin, пароль hardadmin123, Database hardadmin)

При первом запуске создать суперпользователя при желании тестовые данные:

```bash
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py fill_db
```

`fill_db` создаёт 7 отделов, 41 сотрудника, 120 единиц оборудования
и 200 заявок во всех статусах.

Доступы после fill_db:

- HelpDesk: `helpdesk` / `123456`
- сотрудники: `user_000` - `user_039` / `123456`

Очистка тестовых данных:

```bash
docker compose exec web python manage.py delete_test_info
```

Воркер и beat Celery работают отдельными контейнерами,


```bash
docker compose exec web pytest -v
```
